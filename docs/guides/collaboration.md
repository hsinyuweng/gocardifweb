# 與使用者合作的方式（補充 CLAUDE.md）

> 每次要列介面文字或規劃新畫面前讀。有新的合作要求就加在這裡。

## 基本流程

- 使用者是網頁開發新手，有基本程式基礎；一律繁體中文。
- 流程固定：**每個階段先輸出計畫 → 等使用者回覆「確認」→ 才寫程式**（規格第 0 節第 7 條）。規格沒寫清楚的介面文字或行為，列成「需要你確認的介面文字」表格，附建議值，讓使用者一次確認。
- 少量關鍵選擇用 AskUserQuestion 問（建議選項放第一個並標「建議」）。
- 階段完成後：3–5 句說明做了什麼、改了哪些檔案；需要使用者操作的事列成**編號步驟**，寫明**在哪個應用程式（VS Code 終端機）、哪個資料夾（完整路徑＋先給 `cd` 指令）**、輸入什麼、預期看到什麼。
- 使用者驗證後提醒 commit **並 push**（使用者已決定每階段或每次 session 後 commit + push），附建議 commit 訊息與完整指令。
- 指令路徑含中文，`cd` 時要加引號。
- **導覽原則（使用者 2026-10-18 要求，往後所有功能都適用）**：每個能到下一頁或下一步的地方，都要能往回走——畫面上有可點的返回（麵包屑或連結）、瀏覽器「上一頁」有效，而且回到原本的狀態（篩選、選擇保留）。規劃新功能時要在計畫中寫出返回方式。
- 使用者會換對話：重要資訊要寫進 `docs/` 的紀錄（入口 `docs/README.md`）或 CLAUDE.md，不要只留在對話裡。
- **紀錄規則（2026-10-20 使用者要求）**：對網頁本身或整體設計的任何更動，都要直接寫進 `docs/` 的紀錄檔。改動前依 `docs/README.md` 第 3 節，只讀相關範圍的檔案；改動後依第 4 節，按改動大小更新對應的檔案。使用者隨時開新對話，都不能遺失重要細節。
- 使用者提供的架構圖、示意圖存放在 `docs/architecture/diagrams/`。

## 導覽原則的檢查清單（規劃新功能時寫進計畫）

1. 畫面上有可點的返回：麵包屑或「← …」連結。
2. 瀏覽器「上一頁」有效：要新增紀錄的用 push，只是切換篩選的用 replace。
3. 回來時狀態不變：篩選寫進網址，或用 `location.state.from` 帶來源網址。
4. 外部連結一律在新分頁開。
