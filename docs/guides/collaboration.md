# 與使用者合作的方式（補充 /CLAUDE.md）

## 流程

1. 先出計畫：規格沒寫的介面文字與行為列成表（附建議值）；少數關鍵選擇用 AskUserQuestion（建議項放第一並標「建議」）。
2. 等使用者回「確認」才寫程式。
3. 完成後 3–5 句說明；使用者要做的事列成編號步驟：哪個應用程式（VS Code 終端機）、完整路徑（先給加引號的 `cd`）、輸入什麼、預期看到什麼。
4. 使用者驗證後提醒 commit **並 push**，附建議訊息。
- 一律繁體中文。重要資訊寫進 `docs/`，不要只留在對話。
- 紀錄檔要精簡：只寫現況與未來架構，不寫修改過程。

## 導覽原則（所有功能適用）

每個能到下一頁或下一步的地方都要能回來。計畫中要寫出：
1. 畫面上可點的返回（麵包屑或「← …」）。
2. 瀏覽器上一頁有效：新增紀錄用 push，切換篩選用 replace。
3. 回來時狀態不變：篩選寫進網址，或用 `location.state.from`。
4. 外部連結一律新分頁。
