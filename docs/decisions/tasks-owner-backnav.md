# 我的待辦、我的單位、返回路徑（現況）

## 我的待辦 `#/tasks?owner=<單位>`

- **2026-10-27 V6 從左側導覽收起**（使用者決定：事項是 AI 建議、沒有處理狀態，且不確定各單位會自己開網站；之後併入「跨部門審查」）。唯一入口：報告頁「待解決事項」選了負責單位後，篩選旁「看法遵在所有商品的事項 →」（帶 `from`、`fromLabel`，麵包屑「商品 / 我的待辦」，上一頁回報告）。網址照舊可用。
- 跨全部報告彙整某負責單位的待解決事項與建議下一步，**依商品分組**（名稱連報告頁並帶 `?owner=`）。部分報告讀取失敗時其餘照常顯示：「有 N 份報告無法讀取，以下內容不包含：○○、○○。」
- 未選單位或選「全部」：「請選擇負責單位，查看各商品需要處理的事項。」＋單位按鈕「法遵 85」（件數＝待解決＋下一步，多到少）。
- 摘要「待解決事項 N（重大 N）· 建議下一步 N · 涉及 N 件商品」＋「← 所有單位」。商品標題「名稱（發行公司）」＋「看報告 →」。某類無項目顯示「無」；整個單位沒有：「此負責單位沒有相關項目。」
- 排序：重大件數多到少，同數依產出日期新到舊。「上游（顏）」與「上游」分開顯示。列印標題旁「篩選：負責單位＝○○」。
- 重用報告頁 `OwnerFilter`、`BlockersTable`、`NextStepsList`。

## 我的單位（導覽列底部）

- 「我的單位：法遵 更改」／「我的單位：未設定 設定」→ 下拉（第一項「未設定」）＋「取消」。選項＝全部報告的負責單位。
- localStorage `gocardifweb.owner` 只存這個設定；報告頁與我的待辦的下拉只改網址。
- 預設順序：網址 → 我的單位 → 全部。`?owner=`（空值）＝明確選「全部」。

## 返回路徑（導覽原則的實作）

- 競品研究頁的搜尋、篩選、排序寫進網址（`q`、`country`、`category`、`rec`（缺漏＝`__missing__`）、`unread`、`sort`、`dir`；預設值不寫；replace）。
- 進下一頁時用 `location.state.from` 帶來源網址，麵包屑據此決定上一層（`lib/ownerParam.ts` 的 `readFromPath`、`readFromState`）。
- 我的待辦：點單位按鈕 push（上一頁回選單位畫面）；下拉切換 replace。
- 報告頁 E 區分頁列右側「↑ 回到三面向」捲回 C 區。
- **報告頁最上方**（2026-10-27 V3，`components/report/ReportNav.tsx`）：左「← 回競品研究」，依來源改字（回追蹤清單／回新聞與法規監控／回我的待辦／回市場總覽）。站內點進來的用瀏覽器上一頁返回；直接打開網址的連到來源頁（沒有來源時 `#/research`）。右「‹ 上一份 3 / 9 下一份 ›」：順序由競品研究清單帶入 `location.state.order`（目前篩選與排序的快照，看過的報告不會從順序中消失）；從其他頁進來時用競品研究預設排序（產出日期新到舊）。切換報告用 replace，所以上一頁與「← 回…」都直接回清單；網址的 `?owner=` 保留。列印不顯示。
- **回到競品研究清單**：離開前把捲動位置存進 sessionStorage（`gocardifweb.listScroll`，只對同一個篩選網址有效，用過即清），最後看的報告（`gocardifweb.lastReport`）那一列淡黃底標亮 2 秒（`lib/listReturn.ts`）。
- 全部報告由 `RootLayout` 需要時讀一次（`data/allReports.ts`，`useAllReports()`）。
