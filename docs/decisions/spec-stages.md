## 共用

- 時間顯示台北時間到分鐘：`2026-10-11 16:00`。
- 訊息：載入中…／無法讀取資料，請確認網路連線後重新整理頁面。／找不到報告清單。請先執行 npm run sync 匯入報告。／資料格式錯誤，無法顯示。（下一行小字細節）／伺服器發生錯誤，請稍後再試。／後端回 400：「請求格式錯誤，無法取得資料。」＋後端 message（不觸發離線備援）／設定錯誤：config.json 的 dataSource 為 api，但 apiBaseUrl 是空的。
- 導覽列底部「我的單位」「資料更新：…」；選單按鈕 aria-label「開啟選單」「關閉選單」。
- 找不到此頁面＋「回到市場總覽」。

## 競品研究頁 `#/research`（原案件總覽；`#/cases` 以 replace 轉址並保留查詢字串）

- 標題「競品研究」＋「共 N 件 · 資料更新於 …」。
- **第一個畫面**（2026-11-01 使用者回饋，`lib/researchStory.ts`）：
  - 結論兩行，同首頁：「推薦：**CareScout 長照險**（有條件推進）」／「其餘 7 件暫緩：缺商品資料」。
  - 3 張數字卡：推薦（商品簡稱綠色，可直接點進報告頁；下方「沒有阻斷項目」或「卡在：…」）、最常見的卡關原因（大字直接寫原因「保證利率／預定利率未提供」，小字「4 件商品卡在這裡」；同義的卡關寫法歸成一類，至少 2 件才出現；不寫是誰造成的）、台灣潛在市場最大（「267 億元」／商品簡稱）。
  - 「引進分數：越高越值得引進」白卡：每件商品一列橫條（簡稱可點進報告頁｜0–100 長條｜分數），依分數排序；推進的商品綠色、暫緩灰、不建議紅（`components/common/ScoreBar.tsx` 的 `ScoreChart`）。
  - 「全部報告」分隔線之下是建議分布列、搜尋篩選與表格。
- 表格欄：追蹤、商品（簡稱，滑過看全名）、引進分數（數字＋長條，滑過看組成）、整體建議（推進綠、暫緩灰）、潛在市場、法規（「可引進，需修改 7 處」綠／「待確認」）、阻斷（件數＋最嚴重一項）、台灣競品。預設依引進分數高到低（網址不寫 `sort`；同分依建議 → 阻斷少 → 潛在市場大）；法規欄排序：可引進在前。
- **引進分數**（2026-11-01 第二輪，前端計算 `lib/introScore.ts`，在 `normalizeReportIndex` 算好放在 `OverviewRow.score`）：0–100＝建議 50（推進 50、暫緩／未完成 20、不建議 0）＋阻斷 25（0 項 25，每項扣 5，最低 0）＋潛在市場 25（除以清單裡最大的），四捨五入。目前：CareScout 98、Yen Can 57、瑞駿 54、林肯 45、Secure Horizon 44、RapidProtect 40、西北 36、盛裕 25。全站排序（`rankRows`）都用它。後端之後若提供正式分數，改讀後端的。
- 「搜尋商品名稱或發行公司」「全部國家」「全部險種」；「沒有符合條件的案件。」；建議分布列的「全部」不加件數。
- 表格最左欄「追蹤」（2026-10-31，`WatchToggle`）：薰衣草色外框「＋ 追蹤」，已加入時實心「★ 已追蹤」，再按一次移出（提示「加入追蹤清單（不會打開報告）」「已在追蹤清單；再按一次移出」）；點擊與 Enter 都不會打開報告。
- 沒看過（2026-10-31 由「未審閱」改名、降低存在感）：商品名前代表色小圓點（滑過提示「這台瀏覽器還沒打開過這份報告」）；建議分布列最後「● 沒看過 N」開關（網址 `unread=1`，與建議篩選可並用；全部看過時不顯示）。
- 沒看過＝本瀏覽器沒打開過，或報告產出日期已更新（`lib/reviewed.ts`，localStorage `gocardifweb.reviewed`：report_id → 產出日期）。報告頁成功顯示時記為已審閱，日期取報告清單的 generated_date。

## 報告頁

- **版面**（2026-10-27 V4，照閱讀路徑重排，內容不刪；`components/report/ReportView.tsx`）：
  - 最上方「← 回…」與「‹ 上一份 3 / 9 下一份 ›」（見 `tasks-owner-backnav.md`）。
  - ① 頁首：商品名（24px）、「發行公司 · 國家 · 險種 · 幣別 · 繳費」（沒值的項目不列；商品概要已列繳費時這裡不列）；右側「列印／另存 PDF」、產出日期。
  - **商品概要**（2026-11-01，`ProductIntro`、`lib/productIntro.ts`）：白卡，讓保險專業讀者一眼看懂商品在做什麼，照原文用專業詞、不用表格。左欄：小標「商品概要」→ 商品機制一段（16px）→「目標客群」「給付條件」兩行 → 保證項目小標籤（「指數帳戶下限 0%」）＋「附約 …」；右欄（細線分隔；手機改在下方兩欄）：承保年齡、繳費、保障期間、給付、上市。沒值的項目不列；只有英文原文的欄位不列；去掉「（分析）」註記。資料是 `product_snapshot.profile`（目前由 import 從 1.json 帶入）；沒有時用報告的 `mechanism_summary` 當主句。有概要時，判斷理由段落不再列「商品機制」。
  - ② 整體建議標籤（色點＋文字）＋一句摘要（24px）。
  - ③ 四塊：市場需求、發生率暨獲利、法規適用（燈號＋原本的指標、兩行摘要、「看詳細內容 →」切到 E 區分頁）；第四塊「待解決事項」「12 項」（有重大時珊瑚色）「重大 1 · 阻斷 9 · 注意 2」「看待解決事項 ↓」。
  - ④ 「判斷理由」段落：理由清單、品牌定位、商品機制。「待解決事項」段落（右側負責單位篩選）：預設只列重大與阻斷，下方「看全部 12 項（另有注意 2 項）▾」，展開後「收合 ▴」；沒有重大與阻斷時直接全部列出。
  - ⑤ 「建議下一步」段落：先列 5 項，「看全部 8 項 ▾」／「收合 ▴」；再來是下一步條「往下看：三面向細節、資料品質與缺口 ↓」（有競品比較時「往下看：台灣競品比較、三面向細節、資料品質與缺口 ↓」）。
  - 「細節」分隔線之下：台灣競品比較、E 區三面向分頁、資料品質與資料缺口兩欄、商品原始資料、免責聲明。
  - 收合的項目列印時一律印出。底色是競品研究的奶油黃（不論從哪頁進入），卡片白底細框；追蹤按鈕維持薰衣草色。

- C 區燈號旁文字：市場需求＝需求等級標籤、發生率暨獲利＝研究狀態標籤、法規＝overall_verdict；下方指標不重複。
- 文字：產出日期 2026-10-11／判定理由／未提供（原始值：missing）／負責單位／此負責單位沒有相關項目。／下一步編號用 priority 原值，第二行「負責單位：… · 來源面向：…」／疑似輸入錯誤／收合區：資料衝突、證據不一致、缺漏欄位、備註；全空顯示「無」／列印／另存 PDF。
- E 區：摘要／估算方法、目標人口、市場規模估計、信心等級／低估、中估、高估／關鍵發現／來源：…（null「來源：—」）／定價提示：項目、方向、來源數／findings 欄：編號、項目、燈號、法規依據、建議措施、負責單位／燈號篩選含件數（「全部 19」）；「此燈號沒有項目。」
- 市場規模區間條刻度 0 到高估，低到高塗色、中估標點；任一值 null 改純文字。
- 頁尾「免責聲明」；disclaimer null 顯示「—」。
- 列印：選了負責單位就印篩選後內容並註明「篩選：負責單位＝○○」；「全部」不註明。
- 網址或記憶的負責單位不在選項內時視為「全部」，網址不變。
- **加入追蹤清單**（2026-10-31）：頁首商品名稱右側薰衣草色大按鈕「☆ 加入追蹤清單」（40px 高），加入後淡薰衣草「★ 已在追蹤清單」＋「移出」「看追蹤清單 →」；頂部列的同款小按鈕只在頁首大按鈕捲出畫面（被頂部列蓋住也算）後才淡入出現（`VisibilityProbe`）。列印不顯示。
- 法規 findings 表不顯示「編號」欄（2026-10-31：代號已不在其他地方引用）。
- **等級說明**（2026-10-31，`lib/grade.ts`、`components/common/GradeNote.tsx`）：等級本身照原樣（「信心等級 C」「證據等級 A」），說明一律是格子或段落**最下面的 11.5px 灰字**（使用者：一開始看得到、習慣後不礙眼）——市場需求卡片「信心等級：A 最高、C 最低」（在「看詳細內容」上方）、判斷理由段落（理由提到信心時）、市場規模區塊、關鍵發現與差異分析列表下「證據等級：A 最高、C 最低，越高代表證據越直接可靠」（T 開頭「T1 最高、數字越大越低」）、追蹤清單計算明細「級數 1–5，越高越有利；可信度 A 最高、C 最低。」。後端還沒給各等級定義，只寫相對關係。
- **台灣競品比較**（2026-10-31，`sections.market_demand.competitor_comparison`，沒有時不顯示；`CompetitorTable`）：標題「台灣有 3 項直接競品」（另有非直接時「、1 項類似商品」；沒有直接競品「台灣沒有直接競品，列出 N 項類似商品」＋`no_competitor_reason`）。表格欄＝每項競品（名稱、發行公司、「直接競品／類似商品」小標籤、「條款 ↗」新分頁），列＝`comparison_dimensions`（再補屬性裡多出的項目；幣別、繳費方式、與本商品差異有值才列），空格「—」；寬度不夠時表格自己左右捲動。下方「差異分析」依「A級：」「【A級】」「A級（依據）：」分段，每段前「證據等級 A」小標籤。
- **商品原始資料**（2026-10-31，`product_snapshot.source_documents`，目前由 `npm run import` 從 1.json 補上；沒有時不顯示）：頁首基本資料後「原始資料 5 份 ↓」捲到細節區最下方「商品原始資料（5 份）」段落（右上「↑ 回到頁首」）：類型小標籤、標題 ↗（新分頁）、發布日期；列印時附網址。
- 判斷理由開頭若是模組代號（「regulatory：」）換成模組名稱（「法規適用（孫）：」）。
- 後端新欄位（2026-10-20，沒有時不顯示）：一句話結論下方灰字「品牌定位：…（來源）」；關鍵發現「來源：X · 資料日期 …」，X 有網址時是新分頁連結；法規 finding 標題下「來源 ▾」，展開為「可信度 A：說明」與來源清單（列印一律展開）；模組未提供且有 `skip_reason` 時「未提供（原因：…）」取代原始值。

## sync 與 import

- 壞 JSON 或缺 report_id：略過並警告；report_id 含 `/`、`\`、`..` 或為 `index` 也略過；同批 report_id 重複則整批中止。
- `npm run import`（2026-10-31）：`scripts/import-agentdata.mjs` 把 `agentdata/`（後端整包輸出，gitignore）轉到 `incoming/agentdata/`，再 `sync --replace`（整批換新：刪掉這批沒有的舊報告）。轉換只補後端沒給的欄位：報告的發行公司、國家、幣別、繳費方式空著時用 1.json；`product_snapshot.source_documents` 與 `product_snapshot.profile`（商品概要：機制、目標客群、承保年齡、繳費、保障期間、給付方式與條件、保證項目、附約）用 1.json；market-pulse 沒有 `ranking` 時用 `market-pulse-work/output/pulse.json` 的 `company_ranking` 轉成 M7 格式。同商品兩份時在程式的 `SKIP` 選定（目前略過 CareScout `aacd2f35`）；沒有 3.json 的資料夾略過。
