# 競品研究頁、報告頁、使用說明的確認文字與規則（現況）

> 規格沒寫、經使用者確認的部分。規格本身見 `spec/web-spec.md`。

## 共用

- 時間顯示台北時間到分鐘：`2026-10-11 16:00`。
- 訊息：載入中…／無法讀取資料，請確認網路連線後重新整理頁面。／找不到報告清單。請先執行 npm run sync 匯入報告。／資料格式錯誤，無法顯示。（下一行小字細節）／伺服器發生錯誤，請稍後再試。／後端回 400：「請求格式錯誤，無法取得資料。」＋後端 message（不觸發離線備援）／設定錯誤：config.json 的 dataSource 為 api，但 apiBaseUrl 是空的。
- 導覽列底部「資料更新：…」「資料來源：離線資料｜後端連線」；選單按鈕 aria-label「開啟選單」「關閉選單」。
- 找不到此頁面＋「回到市場總覽」。

## 競品研究頁 `#/research`（原案件總覽；`#/cases` 以 replace 轉址並保留查詢字串）

- 標題「競品研究」＋「共 N 件 · 資料更新於 …」。
- 「搜尋商品名稱或發行公司」「全部國家」「全部險種」；「沒有符合條件的案件。」；建議分布列的「全部」不加件數。
- 建議分布列最前面「未審閱 N」開關（網址 `unread=1`），與建議篩選可並用；商品名稱後灰藍標籤「未審閱」。
- 未審閱＝本瀏覽器沒打開過，或報告產出日期已更新（`lib/reviewed.ts`，localStorage `gocardifweb.reviewed`：report_id → 產出日期）。報告頁成功顯示時記為已審閱，日期取報告清單的 generated_date。

## 報告頁

- C 區燈號旁文字：市場需求＝需求等級標籤、發生率暨獲利＝研究狀態標籤、法規＝overall_verdict；下方指標不重複。
- 文字：產出日期 2026-10-11／審閱日期：市場需求 … · …／判定理由／流程列「✓ 完成」，部門審查灰色「規劃中」／未提供（原始值：missing）／負責單位／此負責單位沒有相關項目。／下一步編號用 priority 原值，第二行「負責單位：… · 來源面向：…」／疑似輸入錯誤／收合區：資料衝突、證據不一致、缺漏欄位、備註；全空顯示「無」／列印／另存 PDF。
- E 區：摘要／估算方法、目標人口、市場規模估計、信心等級／低估、中估、高估／關鍵發現／來源：…（null「來源：—」）／定價提示：項目、方向、來源數／findings 欄：編號、項目、燈號、法規依據、建議措施、負責單位／燈號篩選含件數（「全部 19」）；「此燈號沒有項目。」
- 市場規模區間條刻度 0 到高估，低到高塗色、中估標點；任一值 null 改純文字。
- 頁尾「免責聲明」；disclaimer null 顯示「—」。
- 列印：選了負責單位就印篩選後內容並註明「篩選：負責單位＝○○」；「全部」不註明。
- 網址或記憶的負責單位不在選項內時視為「全部」，網址不變。

## 使用說明 `#/guide`

- 第 2 節「首頁四區塊」各一句說明（規劃中的區塊註明）。
- 核心問題表欄名「面向／核心問題」，面向名稱：市場需求、發生率暨獲利、法規適用。

## sync

- 壞 JSON 或缺 report_id：略過並警告；report_id 含 `/`、`\`、`..` 或為 `index` 也略過；同批 report_id 重複則整批中止。

## 部署

- repo 公開；GitHub Actions（Node 24）：push `main` → `npm ci` → `npm run build` → 發布 `dist/`（`.github/workflows/deploy.yml`）。Pages Source＝GitHub Actions。
- 報告資料使用者已確認可公開。
